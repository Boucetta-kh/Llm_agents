Sure! Here are a list of our backend APIs along with their purposes and possible input/output details for these endpoints in more detail:

1. **POST /users** - Sign up as new user endpoint  
The purpose is simply registration, where users fill out an account creation form which includes username (login), password(hashed) and email address respectively to create a unique User ID within the system database with assigned roles ('Admin' or 'Standard'). All inputs are required. The output will be this newly created user details along with their session token for authentication purposes, in JSON format:
```json 
{  
    "user": {...}, //User detail including id and role here.. },    
	"token" : "JWT_TOKEN",//This Jwt Token is returned after successful user registration. It's used for authorization of API calls, like GET/PUT requests on /tasks etc 
}  
```   
2. **POST /login** - Log in to existing account endpoint    
The purpose will be authentication and validation process where the system checks whether provided credentials (username & password) match those stored within database users data or not by hashing it with bcrypt mechanism, then return a session token if validated otherwise an error message. All inputs are required:  username(login),password in plain text for this request
```json  
{    "token" : JWT_TOKEN , //This is returned after successful login and authentication . It's used during further requests to authorize the user          }    
 ```     
3. **GET /tasks** - View all available tasks endpoint  The purpose will be fetching data from database, retrieving lists of existing task for display in JSON format; This request requires a valid session token which is being passed as Authorization Bearer Token (in the header).    Outputs list or errors if not authenticated.
```json  
{     "tasks" : [ ... ], //List containing all tasks retrieved from database }  OR { error: 'Invalid/Expired Session' };     
 ```       
4. **PUT /task/{id}** - Update a specific Task endpoint    The purpose will be to allow users modify the statuses (completed), due dates, etc., of these tasks by updating them in database and returning updated task detail or error if not authenticated  Or with incomplete details(like some required fields are missing). All inputs should include all necessary data for this request.
```json  
{     "task" : { ... }, //Updated Task Detail } OR Error Message;     
 ```       
5. **DELETE /tasks/{id}** - Delete task endpoint  The purpose is to delete a specific tasks from database and return deleted detail or error if not authenticated, with particular id provided in the request body (like deletion of completed/archived Task)     All inputs should include an ID which can identify targeted record.
```json  
{      "task" : { ... }, //Deleted task Detail } OR Error Message; 
 ```       
6. **POST /tasks** - Add new tasks endpoint    The purpose is to allow users add these individual or grouped tasks in database and return added detail, error if not authenticated with required fields missing (like incomplete inputs). All input should be included for this request as JSON format within the body of POST requests
```json  
{     "task" : { ... }, //Added task Detail } OR Error Message;     
 ```       
All other APIs are assumed to require authentication and could return a session token or an error if not validated. All input should be included in JSON format within the body of these requests for POST/PUT operations (like form data).  Note: We use RESTful style API where HTTP methods such as GET,POST , PUT & DELETE are used to perform CRUD Operations on our resources ie tasks and users.
